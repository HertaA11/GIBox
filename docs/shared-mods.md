# 共用转换和模组控制（1.0.18）

源 MOD 仍保存在 GIBox 私有 `files/library`，转换快照保存在 `files/converted`。App 每次导入或重新转换只运行一次转换器，再分发同一份模型、贴图、逻辑文件到各游戏的 `Android/media/<包名>/GIBox/models`。保留分发副本是为了沿用游戏进程已有的目录访问权限；本改动不依赖游戏访问另一个 App 的私有目录。

`files/shared-mod-control.json` 保存统一的 `enabled`、`selected`、`variables`、`keys` 和 `keySeq`。App 将这些字段合入各服的 control.json，其余字段保持该服自己的值。因此骨骼采集请求、调试选项、合成台按钮等不会因另一服的模组操作而被覆盖。游戏运行时仅访问自身目录，Build ID 对应偏移及现场骨骼校验保持原样。

首次迁移优先采用当前所选服的控制与同名转换产物，当前服同一 INI 已保存的整数款式也纳入共用选择。各服旧控制文件保存在 `control-before-shared.json`，冲突的旧转换目录留在该游戏 GIBox 目录下的 `.shared-old-*`。历史按键事件清空，序号取各服最大值，避免升级时重放。

分发不复制 learned.json、texture-mapping.json 和 bonemap-*.tsv。同一份产物再次分发会保留目标服自己的这些记录；转换更新后重新识别。状态、日志、hash-map、骨骼及逻辑程序的运行时存档不跨服复制。App 的显式整数变量及普通循环预设统一分发；运行时只在选择变化时注入，不会每帧钳制 MOD 自身的变量变化。程序驱动的时间线、场景条件和复杂按键仍由各服现场运行。

分发使用暂存目录及目录重命名；失败保留已有的可用产物并报告目标服，之后可以重试分发，不会改为再次转换。转换、迁移与分发串行，避免复制正在重建的模型。删除会记录标记，避免旧服残留在后续迁移时重新复活；重新导入同名 MOD 会清除该标记。

宿主测试覆盖迁移、冲突备份、状态同步、采集请求与日志隔离、现场映射隔离、新安装客户端、复制失败与安全回退、删除和旧产物不复活；native 测试覆盖共用款式优先于客户端旧存档。跨服读目录与实际角色显示仍需真机验证。
